Activation Functions — a 3D Tour

Every neural network is a stack of linear transformations interrupted by nonlinearities. Without those nonlinearities, no matter how deep your network is, the whole thing collapses into a single linear function. The activation function is the nonlinearity. This page explains them in five levels, from layman to mathematical.

What is an activation function? tier 1 · layman

Imagine a neuron is a person making a yes/no decision. They get information (numbers) coming in, weigh how important each piece is, add them up, and then have to decide what to do. The activation function is that decision step.

In the most extreme case, the decision is binary: "is the total above some threshold? Then say yes (1). Otherwise say no (0)." That's the original activation function — the step function. But it has a problem: there's no in-between, no "kind of." In a world of grey, this person can only answer in absolutes.

Modern activation functions are smoother decisions. They take a continuous number in and produce a transformed number out. The shape of that transformation is what makes a network capable of learning anything interesting.

An activation function takes one number, applies some non-linear shape to it, and returns one number. It's the "decision style" of every neuron in the network. The shape you pick has huge consequences for whether the network can learn.

Why we need them tier 2 · the problem

A neural network without activation functions is mathematically the same as a single linear equation, no matter how many layers it has. Here's the trap:

Layer 1: y₁ = W₁ · x + b₁
Layer 2: y₂ = W₂ · y₁ + b₂ = W₂(W₁x + b₁) + b₂
             = (W₂W₁) · x + (W₂b₁ + b₂)
                ↑ this is just another linear layer.

Stack 100 layers without nonlinearities and you still have something equivalent to one linear layer. You can only draw straight lines through your data. You cannot learn to recognize a cat, predict the next word, or anything else interesting.

The activation function breaks this collapse. By applying a non-linear function between layers, you give the network the ability to bend, fold, and reshape its input space — which is what's needed to learn anything beyond linear regression.

Look at the 3D viewer above. Watch what the function does to the orange particles flowing in along the x-axis: it bends them, clips them, smooths them. That bending is what makes deep learning possible.

1. Step function (historical) where it all started

Open the 3D viewer above and click Step.

Tier 1 · Layman

The light switch

This is the simplest decision rule in the world: a light switch. Is the input above zero? Output is 1 (on). Below zero? Output is 0 (off). No gradations, no "maybe," no shades of grey.

Tier 2 · The problem it solves

Modeling a biological neuron

McCulloch and Pitts proposed this in 1943, decades before backpropagation. Biological neurons fire in discrete spikes — either they fire or they don't. The step function was the natural mathematical model. The 1957 Perceptron (Rosenblatt) used this activation and was the first machine learning model trained on real data.

Tier 3 · Visual intuition

A perfect cliff at zero

Imagine a flat plane at height 0 stretching to the left, then at exactly x=0, a vertical wall jumping straight up to height 1, then continuing flat at height 1 forever to the right. No curve, just two horizontal lines connected by a vertical jump.

Tier 4 · Mathematical

f(x) = 1 if x ≥ 0 else 0

Also known as the Heaviside step function. It's piecewise constant — it equals 1 for all non-negative inputs and 0 for all negative inputs.

Tier 5 · Advanced (why we don't use it anymore)

The killer: zero derivative

The derivative is 0 everywhere except at x=0, where it's technically undefined (you can think of it as a Dirac delta with infinite slope). For gradient descent, this is catastrophic — if your gradient is 0 everywhere, there's no information about which direction to update weights. The step function is a dead end for learning by backpropagation.

The Perceptron got around this by training with a non-gradient-based rule. But once backprop became the standard, step functions disappeared from the lineup.

Pros

  • Conceptually simple — yes or no
  • Computationally trivial (one comparison)
  • Biologically plausible

Cons

  • Zero gradient everywhere — fatal for backprop
  • Not differentiable at x=0
  • Loses all magnitude information (1 vs 1000 → same output)

2. Sigmoid the smooth yes/no

Tier 1 · Layman

"How confident are you?" (0% to 100%)

Instead of a hard yes or no, sigmoid gives you a confidence percentage. Big positive number going in? "I'm very confident, like 99%." Big negative? "Very unlikely, 1%." Right around zero? "Honestly, 50/50."

It's the soft version of the light switch — a dimmer that smoothly transitions from off to on as you turn the knob.

Tier 2 · The problem it solves

Making learning differentiable

The step function couldn't be trained with gradient descent because its derivative was zero everywhere. Sigmoid solved that by being a smooth S-curve — at every point, you can compute "if I nudge x a little, how much does the output change?" That tiny piece of information is what lets gradient descent work.

It also has a beautiful property: its output is always between 0 and 1, so it can be interpreted as a probability. For decades (1980s-2010), sigmoid was the default activation in neural networks.

Tier 3 · Visual intuition

An S-curve hugged between 0 and 1

The curve is dead flat near 0 on the left side (large negative inputs), shoots up sharply through the middle (around x=0, the output is 0.5), then flattens out again near 1 on the right side. The steepest part of the slope is right at x=0.

Look at the 3D viewer with sigmoid selected. Notice the particles getting compressed into a narrow band between 0 and 1 — that's the squashing effect.

Tier 4 · Mathematical

σ(x) = 1 / (1 + e⁻ˣ)

Equivalent forms:

σ(x) = 1 / (1 + e⁻ˣ)            # standard form
     = eˣ / (1 + eˣ)            # multiply top and bottom by eˣ
     = (1 + tanh(x/2)) / 2      # related to tanh by a shift+scale

σ(0) = 0.5. As x → +∞, σ(x) → 1. As x → −∞, σ(x) → 0. Always strictly between 0 and 1.

Tier 5 · Advanced (the vanishing gradient story)

σ'(x) = σ(x) · (1 − σ(x))

Beautiful closed form, but here's the killer: the maximum value of this derivative is exactly 0.25, occurring at x=0. As x moves away from zero in either direction, the derivative falls toward 0.

That means every sigmoid layer multiplies your gradient by at most 0.25. Stack 10 sigmoid layers and your gradient signal becomes (0.25)¹⁰ ≈ 1e-6. The deepest layers in a sigmoid network barely learn anything — the gradient signal has vanished by the time it gets to them. This is the vanishing gradient problem, the central reason deep networks didn't work pre-2010.

Sigmoid is still used today, but only at output layers (binary classification) — never as the hidden-layer activation in deep networks.

Pros

  • Smooth, fully differentiable
  • Output ∈ (0, 1) — usable as probability
  • Mathematically elegant derivative

Cons

  • Vanishing gradients — max derivative is just 0.25
  • Not zero-centered — outputs always positive
  • Saturates: huge inputs give nearly identical outputs
  • Exponential is more expensive than ReLU

3. Tanh sigmoid's zero-centered cousin

Tier 1 · Layman

Sigmoid, but it can also say "no"

Sigmoid only ever outputs positive numbers (between 0 and 1). Tanh is the same S-shape, but it's centered around zero — so it can say "negative" or "positive" with equal force. Outputs range from -1 to +1.

Tier 2 · The problem it solves

"Zero-centered" matters for training

Because sigmoid outputs are always positive, the gradients flowing back through a layer of sigmoid neurons are always in the same direction (all positive or all negative) — which forces zig-zag updates and slows training. Tanh outputs can be either sign, so the gradients are zero-centered too. Training tends to be a bit faster, and was the standard choice for RNNs (LSTMs, GRUs) before ReLU dominance.

Tier 3 · Visual intuition

S-shape, but symmetric around (0, 0)

The curve passes through the origin. Far to the left, it asymptotes to -1; far to the right, it asymptotes to +1. The steepest slope is at x=0, just like sigmoid.

Tier 4 · Mathematical

tanh(x) = (eˣ − e⁻ˣ) / (eˣ + e⁻ˣ)

tanh(x) = 2·σ(2x) − 1           # tanh is literally a rescaled sigmoid
        = sinh(x) / cosh(x)     # ratio of hyperbolic sin/cos

tanh(0) = 0. tanh(±∞) = ±1.

Tier 5 · Advanced

tanh'(x) = 1 − tanh²(x)

Maximum derivative is 1.0 at x=0 — four times better than sigmoid's 0.25. So vanishing gradients are less severe than with sigmoid, but still a problem in deep networks: tanh still saturates for large |x|.

Tanh used to be the default activation in RNNs (LSTM, GRU) and is still used inside their gating mechanisms. For feedforward layers, ReLU and its variants have largely replaced it.

Pros

  • Zero-centered output (range -1 to 1)
  • Better max gradient than sigmoid (1.0 vs 0.25)
  • Smooth and differentiable everywhere

Cons

  • Still saturates at extreme inputs
  • Still suffers vanishing gradient (just less than sigmoid)
  • Exponential is expensive vs ReLU

4. ReLU the breakthrough · 2010

Tier 1 · Layman

The one-way valve

Imagine a one-way water valve. Water flowing in the positive direction? Passes through freely, unchanged. Water trying to flow backward (negative)? Blocked completely.

ReLU does this for numbers. Positive inputs pass through as-is. Negative inputs become exactly zero. That's the whole activation function.

Tier 2 · The problem it solves

It made deep networks actually train

For 20+ years, deep neural networks "couldn't work" — they'd stop improving past 4-5 layers because of the vanishing gradient problem (sigmoid and tanh both saturate). In 2010, researchers showed that ReLU's gradient is exactly 1 for positive inputs, so it doesn't shrink as you stack layers.

This single change — replacing sigmoid with ReLU — is what made AlexNet (2012) possible, which kicked off the deep learning revolution. Almost every modern network uses ReLU or one of its derivatives.

Tier 3 · Visual intuition

Two straight lines meeting at the origin

To the left of zero: a flat floor at height 0. To the right of zero: a 45-degree ramp going up at slope 1. They meet at a sharp corner at the origin. That's it.

In the 3D viewer with ReLU selected, notice how all the particles to the left of zero get squished onto the floor (y=0), while particles to the right ride up the ramp unchanged.

Tier 4 · Mathematical

f(x) = max(0, x)

One comparison. No exponentials, no division. ReLU is also the cheapest activation to compute — a single conditional.

def relu(x):
    return max(0, x)
# or for tensors:
def relu(x):
    return torch.clamp(x, min=0)
Tier 5 · Advanced (the dying ReLU problem)

f'(x) = 1 if x > 0 else 0

The derivative is a step function — 1 for positive, 0 for negative. Technically undefined at exactly x=0 but PyTorch just picks 0 there.

The "dying ReLU" problem: if a neuron's pre-activation drifts permanently negative (e.g., from one bad gradient update that pushed weights too far), its gradient becomes 0 forever. The neuron stops learning, stops contributing, and is effectively dead. In some networks, 20-40% of ReLU neurons can be "dead" by the end of training.

Symptoms in your training:

  • Whole channels of activations frozen at 0 for all inputs
  • Loss plateaus surprisingly
  • Lowering the learning rate sometimes helps

Fixes: Leaky ReLU, ELU, GELU, careful initialization (Kaiming/He init was designed for ReLU).

Pros

  • Cheapest activation possible — one comparison
  • No vanishing gradient for positive inputs
  • Sparse activations (many neurons output exactly 0)
  • Single-handedly enabled deep learning

Cons

  • Dying ReLU — dead neurons never recover
  • Not zero-centered (outputs ≥ 0)
  • Non-differentiable at x=0 (small practical issue)
  • Unbounded above (exploding activations possible)

5. Leaky ReLU ReLU with a tiny leak

Tier 1 · Layman

The one-way valve, but a little water seeps through

ReLU was a perfect valve — blocks negative completely. Leaky ReLU is a slightly imperfect valve: most of the time it blocks negatives, but a tiny amount still leaks through. Specifically, negative inputs get multiplied by 0.01 instead of being killed outright.

Tier 2 · The problem it solves

Fixes "dying ReLU"

The problem with vanilla ReLU is that dead neurons stay dead — once a neuron's pre-activation is negative, its gradient is 0, and it can't recover. Leaky ReLU has a small but non-zero gradient (typically α=0.01) for negative inputs, so dead neurons can still receive a learning signal and potentially come back to life.

Tier 3 · Visual intuition

Two lines still, but the left one has a very gentle upward slope

Same as ReLU on the positive side. On the negative side, instead of being flat at zero, the line slopes upward very gently (slope 0.01 instead of 0). Visually almost indistinguishable from ReLU unless you zoom way in.

Tier 4 · Mathematical

f(x) = max(α·x, x), with α ≈ 0.01

Equivalent piecewise form:

f(x) = x          if x > 0
     = α·x        if x ≤ 0      (α typically 0.01)

Variants:

  • PReLU (Parametric ReLU): α is a learned parameter per channel, not a fixed constant.
  • RReLU (Randomized): α is sampled uniformly from some range during training (acts as regularization).
Tier 5 · Advanced

f'(x) = 1 if x > 0 else α

The derivative is α for negative inputs instead of 0. No dead neurons.

The empirical gain over ReLU is small — often less than 1% improvement on standard benchmarks. The reasoning is that in modern architectures with careful initialization (Kaiming init), batch normalization, and skip connections, dying ReLU is less of a concern. But on small networks or those without batch norm, Leaky ReLU is a cheap insurance policy.

Pros

  • Eliminates dying ReLU problem
  • Still very cheap (one comparison + multiply)
  • Non-zero gradient everywhere

Cons

  • α is an extra hyperparameter to set
  • Empirical gain over ReLU is small (~0.5-1%)
  • Still not zero-centered

6. GELU the transformer default

Tier 1 · Layman

ReLU's smoother, smarter cousin

ReLU has a hard corner at zero — abruptly switching from "pass through" to "completely block." GELU smooths that corner. Instead of a sharp cliff, it's a gentle curve. Small negative values aren't completely killed; they're just heavily reduced. Most of the same benefits, none of the dying-neuron sharpness.

Tier 2 · The problem it solves

Better gradients for transformers

The sharp corner of ReLU creates discontinuous gradients (1 vs 0 with no gradient transition). Empirically, transformers (BERT, GPT, LLaMA, modern image transformers) train better with smooth activations. GELU is the dominant choice. Modern image diffusion models and most ViT-style architectures use GELU.

It also has a probabilistic interpretation: GELU is essentially "multiply your input by the probability that the input is positive under a standard normal distribution" — a kind of stochastic-but-deterministic gating.

Tier 3 · Visual intuition

Like ReLU, but with the corner softened into a curve

For large positive x, GELU looks just like a 45-degree line (same as ReLU). For large negative x, GELU is essentially zero. The interesting part is the middle: a smooth S-shaped curve that briefly dips below zero around x ≈ -1 before approaching zero asymptotically.

That tiny dip — outputs going slightly negative for some negative inputs — is a key difference from ReLU.

Tier 4 · Mathematical

f(x) = x · Φ(x)

Where Φ is the cumulative distribution function of the standard normal distribution. In plain English: f(x) is the input x multiplied by "the probability that a random standard-normal sample is less than x."

Practical implementations use a tanh-based approximation that's much faster to compute:

GELU(x) ≈ x · 0.5 · (1 + tanh(√(2/π) · (x + 0.044715·x³)))
        ≈ x · σ(1.702·x)                  # cheaper sigmoid approximation

PyTorch's F.gelu() uses one of these — choose 'tanh' or 'none' approximation.

Tier 5 · Advanced

Why GELU dominates in transformers

The derivative is messy but always well-defined — no discontinuities. Combined with the smooth curve, this means:

  • No dead neurons: negative inputs still produce small non-zero gradients
  • Better optimization landscape: smoother gradients lead to smoother loss surfaces
  • Self-gating interpretation: f(x) = x · Φ(x) is like ReLU but with a probabilistic "gate" instead of a hard cutoff

GELU is the default in BERT, GPT-2/3, LLaMA-family, ViT, DiT (the architecture you'll build in Phase 3). When in doubt for a transformer-style model, use GELU.

Pros

  • Smooth everywhere — no dead neurons
  • Empirically beats ReLU on language tasks
  • Probabilistic interpretation
  • The de-facto choice for transformers

Cons

  • ~2-3× more expensive than ReLU
  • Formula is more complex (multiple variants)
  • Marginal gain on CNN-style tasks

7. SiLU / Swish used in LLaMA, modern image gen

Tier 1 · Layman

"x times its own confidence"

SiLU (also called Swish) is the input multiplied by its own sigmoid. In plain terms: "look at the input, decide how confident you are that it's positive (using sigmoid), then output the input scaled by that confidence." Big positive → high confidence → passes through. Big negative → low confidence → near zero.

Tier 2 · The problem it solves

A simpler GELU that works just as well

Discovered via neural architecture search by Google in 2017 (originally "Swish"; later renamed SiLU for "Sigmoid Linear Unit"). It performs comparably to GELU but is cheaper to compute. Used heavily in modern open-source LLMs (LLaMA family), Stable Diffusion's U-Net, and recent ViT variants.

Tier 3 · Visual intuition

Looks like GELU, with a slightly deeper dip

For large positive x, behaves like a 45-degree line. For large negative x, approaches zero. Between, there's a smooth curve with a small dip below zero around x ≈ -1.3 (where it has its global minimum of about -0.28).

Tier 4 · Mathematical

f(x) = x · σ(x) = x / (1 + e⁻ˣ)

That's it. Just sigmoid multiplied by the input. Notice it's strictly cheaper than GELU's tanh-based approximation: one exponential vs three multiplications and a tanh.

A parametric version, Swish-β, has f(x) = x · σ(β·x) where β is learnable. β=1 (the default) gives SiLU; β=0 gives a linear function; large β approaches ReLU.

Tier 5 · Advanced

f'(x) = σ(x) + x · σ(x) · (1 − σ(x))

Can be rewritten as f'(x) = σ(x) · (1 + x · (1 − σ(x))), which is computed efficiently.

The "self-gating" property — input scaled by its own sigmoid — empirically gives smoother gradient flow than ReLU. In transformers like LLaMA, SiLU is used inside the SwiGLU MLP variant: SwiGLU(x) = SiLU(W₁x) ⊙ (W₂x) — a gated linear unit with SiLU as the gate.

Bottom line: SiLU is "GELU but cheaper, with nearly identical performance." When you're building modern LLMs or image generators, this is the standard choice in 2026.

Pros

  • Cheaper than GELU (single exp instead of three multiplies + tanh)
  • Performs comparably to GELU on most tasks
  • Smooth, no dead neurons
  • Used in LLaMA, Stable Diffusion, modern ViT

Cons

  • Slightly more expensive than ReLU
  • Marginal gain over GELU is small
  • Less interpretable than ReLU's "valve" mental model

8. Softmax the output-layer specialist

Tier 1 · Layman

"Force these scores into percentages that sum to 100%"

Different from the others — Softmax takes a whole vector of scores and turns them into probabilities. If a network outputs scores [3.0, 1.0, 0.5] for three classes ("cat", "dog", "fish"), softmax will turn them into something like [0.78, 0.13, 0.09] — three numbers that sum to 1 and can be read as "78% cat, 13% dog, 9% fish."

Tier 2 · The problem it solves

Multi-class probabilities at the output

For a classifier with K classes, you need K outputs that:

  • Are all non-negative (probabilities)
  • Sum to exactly 1 (one of the classes is correct)
  • Reflect the relative confidence between classes

Softmax does this. It exponentiates each score (making them all positive) and then divides each by the sum (forcing them to sum to 1). The larger a score, the more it dominates after exponentiation — which is why softmax is "soft argmax": it's a smooth differentiable version of "pick the largest."

Tier 3 · Visual intuition (interactive)

Three sliders → three bars

Tier 4 · Mathematical

softmax(x)ᵢ = eˣⁱ / Σⱼ eˣʲ

For a vector x = [x₁, x₂, ..., xₖ]:

  1. Exponentiate each: [e^x₁, e^x₂, ..., e^xₖ]
  2. Sum them: S = Σⱼ e^xⱼ
  3. Divide each by S: probabilities = [e^x₁/S, e^x₂/S, ..., e^xₖ/S]

Always sums to 1. Always positive. The output is a valid probability distribution.

Tier 5 · Advanced

Numerical stability + cross-entropy

The naive formula has a numerical stability problem: if any xᵢ is large (say 1000), then e^xᵢ overflows. The standard trick is to subtract the max before exponentiating:

m = max(x)
softmax(x)ᵢ = e^(xᵢ − m) / Σⱼ e^(xⱼ − m)

Mathematically identical (the m's cancel), but now the largest exponent is e^0 = 1, no overflow. PyTorch's F.softmax() does this automatically.

The cross-entropy partnership: when paired with cross-entropy loss for classification, the combined gradient simplifies beautifully to (predicted_probs − one_hot_target). This is why nn.CrossEntropyLoss in PyTorch expects raw logits, not softmax outputs — it computes softmax + log + cross-entropy in a numerically stable fused operation.

Common bug: applying softmax in your model AND using CrossEntropyLoss → double softmax → silently wrong training. Always pass raw logits to CrossEntropyLoss.

Pros

  • Produces a valid probability distribution
  • Differentiable everywhere
  • Pairs beautifully with cross-entropy loss
  • The de-facto choice for multi-class output

Cons

  • Computationally expensive at large vocab sizes (e.g., LLMs)
  • Needs the max-subtraction trick for numerical stability
  • Easy to misuse (double-softmax bug)
  • Only suitable as an output activation — not for hidden layers

How to pick (decision tree) practical guide

Default rule for 2026: use GELU for transformers (NLP, ViT, DiT). Use SiLU for LLM-style models (LLaMA family) and modern image generators. Use ReLU for CNNs. Use Softmax only at multi-class output. Don't use sigmoid or tanh in hidden layers of deep networks.

By architecture

  • Transformer (BERT, GPT, ViT, DiT): GELU (default) or SiLU (in modern variants).
  • LLM (LLaMA, Mistral): SiLU, used in SwiGLU MLP layers.
  • Diffusion model U-Net: SiLU. Inside DiT-style: GELU.
  • Convolutional network (ResNet, etc.): ReLU. Leaky ReLU if you suspect dying-neuron issues.
  • GAN discriminator: Leaky ReLU (typical α=0.2 here, not 0.01).
  • RNN / LSTM / GRU: Tanh inside the cell, sigmoid for gates (these are baked-in choices, not yours).
  • Final output for binary classification: Sigmoid + BCEWithLogitsLoss (use the with-logits version).
  • Final output for multi-class classification: Softmax — but pass raw logits to CrossEntropyLoss; don't apply softmax in the model.
  • Final output for regression: no activation. Just a linear layer.

Common combinations that work well

  • SwiGLU (in LLaMA): SiLU(W₁x) ⊙ (W₂x) — gated linear unit with SiLU as the gate. Standard in modern LLMs.
  • GeGLU: GELU(W₁x) ⊙ (W₂x) — same idea with GELU.
  • Mish: x · tanh(softplus(x)) — niche but used in some CV work.
