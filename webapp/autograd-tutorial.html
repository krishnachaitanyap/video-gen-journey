How autograd actually works — interactively

Pick an expression. Step through the forward pass, then the backward pass. Watch each tensor's .grad fill in. This is exactly what PyTorch does under the hood — just smaller and slower so you can see it.

The one-paragraph version

Autograd is reverse-mode automatic differentiation. As you do operations on a tensor with requires_grad=True, PyTorch silently builds a DAG where nodes are tensors and edges record how each tensor was produced. When you call loss.backward(), autograd walks that DAG in reverse, applying the chain rule at each edge, and accumulates gradients into the .grad field of every leaf tensor that fed into the loss.

Same example, three views

Take a single computation — y = x³ + 2x at x = 2:

import torch
x = torch.tensor(2.0, requires_grad=True)
y = x ** 3 + 2 * x
y.backward()
print(x.grad)   # 3x² + 2 = 14.0

Eight ways to create autograd-enabled tensors

PyTorch gives you several entry points into the autograd graph. They all build the same DAG; they differ in ergonomics and intent.

Way 1 · explicit constructor

torch.tensor(..., requires_grad=True)

x = torch.tensor([2.0, 3.0], requires_grad=True)
y = (x ** 2).sum()
y.backward()
print(x.grad)        # tensor([4., 6.])
When: the most explicit form. Use when you're constructing a new leaf tensor from data and want it in the graph from the start.
Way 2 · in-place opt-in

x.requires_grad_(True)

x = torch.randn(10)
x.requires_grad_(True)        # mutates x in place
y = (x ** 2).sum()
y.backward()
print(x.grad.shape)           # torch.Size([10])
When: you already have a tensor (e.g., loaded from a file) and want to enable gradients without recreating it. Note the trailing underscore — PyTorch convention for in-place mutation.
Way 3 · derived tensors

Just operate on a leaf

x = torch.tensor(2.0, requires_grad=True)
# y inherits requires_grad — automatically
y = x ** 3 + 2 * x
print(y.requires_grad, y.grad_fn)
# True  <AddBackward0>
When: almost all the time. Any tensor produced by ops on a requires_grad=True tensor automatically has requires_grad=True and a grad_fn pointing at the op that produced it.
Way 4 · learned parameters

nn.Parameter(...)

import torch.nn as nn
W = nn.Parameter(torch.randn(10, 5))
# requires_grad=True by default
# When assigned to an nn.Module attribute,
# it's auto-registered for optim and FSDP.
When: defining learnable weights in a module. nn.Parameter is just a Tensor with requires_grad=True + special registration behavior.
Way 5 · nn.Module auto-registration

Standard layers

linear = nn.Linear(10, 5)
# Internally:
#   self.weight = nn.Parameter(torch.empty(5, 10))
#   self.bias   = nn.Parameter(torch.empty(5))
# Both already have requires_grad=True.
for p in linear.parameters():
    print(p.shape, p.requires_grad)
When: using any built-in layer. You never call requires_grad=True manually; the modules do it.
Way 6 · custom function

torch.autograd.Function

class MyReLU(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        ctx.save_for_backward(x)
        return x.clamp(min=0)
    @staticmethod
    def backward(ctx, grad_out):
        x, = ctx.saved_tensors
        return grad_out * (x > 0).float()

y = MyReLU.apply(x)            # plugs into autograd
When: you need a custom op with custom backward — for performance, for numerical stability, or to wrap a non-differentiable approximation with a surrogate gradient.
Way 7 · context — disable

with torch.no_grad():

x = torch.tensor(2.0, requires_grad=True)
with torch.no_grad():
    y = x ** 3                # y.requires_grad == False
# No graph built. Use at eval time + during sampling.
# Significant memory + speed gain.
When: inference, evaluation, sampling. Or any time you compute something with grad-enabled tensors but don't want a graph (e.g., logging).
Way 8 · break the graph

tensor.detach()

x = torch.tensor(2.0, requires_grad=True)
y = x ** 3
z = y.detach() + 5
# z shares storage with y, but is OUT of the graph.
# Backward through z stops at the detach.
print(z.requires_grad)       # False
When: using a tensor's value as a constant — target networks in RL, gradient stopping in distillation (concept 44), caching for logging without growing the graph.

Common pitfalls

1. Forgetting optimizer.zero_grad()

Gradients accumulate on each .backward(). Without zeroing, batch N's gradient contains contributions from batches 1..N-1, the LR effectively grows, loss diverges. (Gradient accumulation — intentionally calling .backward() multiple times before step() — relies on this same behavior.)

2. Calling .backward() twice without retain_graph=True

The graph is freed after backward to reclaim memory. Re-calling raises RuntimeError: Trying to backward through the graph a second time. If you genuinely need multiple backward passes (rare — usually only in second-order methods), pass retain_graph=True on the first call.

3. In-place ops on tensors needed for backward

x.add_(1) mutates x in place. If x's pre-mutation value was needed by some saved-for-backward op, you get RuntimeError: one of the variables needed for gradient computation has been modified by an inplace operation. Fix: use the non-in-place version (x = x + 1) or clone first.

4. Trying to read .grad on a non-leaf tensor

By default .grad is only populated on leaf tensors (created by the user, not derived from ops). For an intermediate tensor, either call .retain_grad() before backward, or use torch.autograd.grad(out, [intermediate]) directly.

5. Forgetting model.eval() + torch.no_grad() at inference

model.eval() switches Dropout/BatchNorm to eval mode. no_grad() tells autograd not to build a graph. Forget either and your eval is biased and uses 2-3× more memory than necessary.

Try it in Colab

The same examples, but in real PyTorch — copy this into a Colab cell:

!pip install -q torch
import torch

# Example: y = x³ + 2x  at x = 2
x = torch.tensor(2.0, requires_grad=True)
y = x ** 3 + 2 * x
y.backward()
print("y     =", y.item())          # 12.0
print("dy/dx =", x.grad.item())     # 14.0  (3·2² + 2)

# Verify with a different point
x.grad.zero_()                      # IMPORTANT — gradients accumulate
x.data = torch.tensor(3.0)
y2 = x ** 3 + 2 * x
y2.backward()
print("dy/dx at x=3:", x.grad.item())   # 29.0  (3·3² + 2)
